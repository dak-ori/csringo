요약
==================================================
컴퓨터과학(CS) 학습에서 반복 연습은 개념 이해와 문제 해결 능력을 강화하는 핵심 수단이다.
그러나 기존 학습 자료는 정적이며 학습자 수준에 맞는 맞춤형 문제 제공이 어렵다. 본 논문에서는
이러한 한계를 극복하기 위해 LLM(대규모 언어모델)을 활용한 한국어 컴퓨터과학 학습 웹 애플리케이션
CS링고(CSRingo)를 설계 및 구현한다. 제안 시스템은 Next.js 프론트엔드, Supabase 백엔드,
Anthropic Claude API로 구성되며, 빈칸 채우기·순서 배열·논리 흐름의 세 가지 문제 유형과
자료구조·알고리즘·운영체제·네트워크 4개 CS 영역을 지원한다. 오답 이력을 분석하여 Claude AI가
복습 우선순위를 산정하고 개인화 복습 큐를 자동 생성하는 파이프라인을 적용하였으며, XP·레벨·
하트·연속 학습 스트릭 기반의 게이미피케이션 요소를 도입하여 학습 지속성을 높인다. 구현 결과
4개 과목 11개 챕터 27개 문항을 포함한 콘텐츠를 제공하며, AI 기반 복습 큐 생성 응답 시간은
256 토큰 제한 하에 평균 1~2초 수준으로 측정되었다.

I. 서론
==================================================
컴퓨터과학 학습에서 연습문제는 개념 이해와 문제 해결 능력을 강화하는 핵심 도구이다. 그러나
기존 교재나 학습 플랫폼이 제공하는 문제는 정적이며, 학습자 수준이나 취약 개념에 따른 맞춤형
제공이 어렵다. 특히 한국어로 CS를 학습하는 환경에서는 양질의 연습문제 자원이 부족하다.

최근 GPT, Claude와 같은 대규모 언어모델(LLM)의 발전으로 교육용 문제 자동 생성에 대한
관심이 높아지고 있다[1, 2]. LLM은 주어진 개념과 난이도에 맞는 문제를 즉시 생성할 수 있으나,
학습 효과를 높이기 위해서는 단순 생성을 넘어 개별 학습자의 오답 이력을 반영한 개인화가 필요하다.

본 논문에서는 이를 위해 LLM 기반 한국어 CS 학습 웹 애플리케이션 CS링고를 제안한다.
제안 시스템의 핵심은 학습자가 틀린 문제를 AI가 분석하여 복습 우선순위를 자동 산정하고
개인화 복습 큐를 생성하는 파이프라인이다. 여기에 XP, 레벨, 하트, 연속 학습 스트릭 등
게이미피케이션 요소를 결합하여 학습 지속성을 높인다.

본 논문의 구성은 다음과 같다. II장에서 관련 연구를 고찰하고, III장에서 시스템 설계 및
구현을 기술하며, IV장에서 구현 결과를 평가하고, V장에서 결론 및 향후 과제를 제시한다.


==================================================
II. 관련 연구
==================================================
2.1 LLM 기반 교육용 문제 생성

Kurdi 외[1]는 교육 목적 자동 문제 생성에 관한 체계적 문헌 조사를 통해, 빈칸 채우기·
선택형·단답형 등 다양한 유형의 자동 생성이 학습 효과를 높임을 확인하였다. Brown 외[2]는
GPT-3을 활용한 퓨샷 학습으로 다양한 형식의 문제를 생성할 수 있음을 보였으며, 이후 Claude,
GPT-4 등 더 강력한 모델들이 교육 콘텐츠 생성에 활발히 적용되고 있다.

2.2 LLM 출력 품질 향상

Madaan 외[3]는 Self-Refine 기법을 통해 LLM이 자신의 출력을 반복적으로 개선할 수 있음을
제안하였다. Zheng 외[4]는 LLM-as-a-Judge 방법으로 다른 LLM의 출력 품질을 평가하는
접근법을 제시하였다. 이러한 연구들은 LLM 출력에 검증 루프를 적용하는 것이 품질 향상에
유효함을 시사한다.

2.3 게이미피케이션과 학습 동기

Duolingo 등 게이미피케이션 기반 언어 학습 앱은 XP, 스트릭, 리그 시스템이 학습 지속성에
긍정적 영향을 미침을 실증하였다. 본 연구에서는 이 설계 원칙을 CS 학습에 적용한다.

III. 시스템 설계 및 구현
==================================================
3.1 시스템 구성

제안 시스템 CS링고는 다음 세 계층으로 구성된다.

- 프론트엔드: Next.js 14 (App Router), React, Tailwind CSS, shadcn/ui
- 백엔드: Supabase (PostgreSQL, Row Level Security, OAuth 인증)
- AI 계층: Anthropic Claude API (claude-haiku-4-5-20251001)

모든 데이터는 Supabase PostgreSQL에 저장되며, 인증은 Supabase OAuth를 통해 처리된다.
미들웨어에서 세션을 검증하여 비인증 사용자의 보호 라우트 접근을 차단한다.

3.2 데이터 모델

핵심 테이블 구조는 다음과 같다.

- courses / chapters / lessons / problems: 콘텐츠 계층 구조
- profiles: 학습자 프로파일 (hearts, streak, total_xp, league)
- user_progress: 레슨 완료 이력
- wrong_answers: 오답 이력 (problem_id, wrong_count, last_wrong_at)
- review_queue: AI 생성 복습 큐 (problem_id, priority, reviewed_at)
- xp_logs: XP 변동 이력

3.3 콘텐츠 구조

총 4개 과목, 9개 챕터, 12개 레슨, 27개 문제를 제공한다.

[표 1. 구현된 콘텐츠 규모]
--------------------------------------------------
과목          | 챕터 수 | 레슨 수 | 문제 수
--------------------------------------------------
자료구조      |    3    |    5    |   13
알고리즘      |    2    |    3    |    6
운영체제      |    2    |    2    |    4
네트워크      |    2    |    2    |    4
--------------------------------------------------
합계          |    9    |   12    |   27
--------------------------------------------------

문제 유형은 세 가지이다.

- fill_blank(빈칸 채우기): 개념어를 직접 입력
- drag_order(순서 배열): 항목을 올바른 순서로 정렬
- logic_flow(논리 흐름): 주어진 흐름에서 빈 단계의 보기를 선택

각 문제는 concept_tags, xp_reward, hint 필드를 가지며, 정답 채점은 서버에서
대소문자·공백을 정규화한 후 배열 순서 비교로 수행한다.

3.4 학습 플로우

레슨은 카드(card) → 문제(problem) → 완료(complete) 세 단계로 진행된다.

1. 카드 단계: 개념 설명 카드를 슬라이드 형태로 제시한다.
2. 문제 단계: 유형에 따른 인터랙티브 문제를 순서대로 풀이한다.
   - 정답 시: XP 지급 및 xp_logs 기록
   - 오답 시: 하트 1개 소모, wrong_answers 카운트 증가
3. 완료 단계: 레슨 XP 지급, 스트릭 갱신, 레벨업 여부 반환

3.5 AI 기반 복습 큐 생성 파이프라인

레슨 완료 시 비동기(fire-and-forget) 방식으로 복습 큐 생성 파이프라인이 실행된다.
파이프라인은 다음 4단계로 구성된다.

① 수집 단계: wrong_answers 테이블에서 wrong_count ≥ 2인 문제를 최대 20개 조회한다.
② 분석 단계: 오답 문제 목록(problem_id, wrong_count, concept_tags)을
   Claude API에 전달하여 복습 우선순위(1~5)를 JSON 형식으로 반환받는다.
   프롬프트는 틀린 횟수가 많은 순으로 상위 5개를 선정하도록 지시한다.
   max_tokens=256으로 제한하여 응답 속도와 비용을 최적화한다.
③ 폴백(fallback): API 오류 시 틀린 횟수 내림차순으로 상위 5개를 자동 선정한다.
④ 저장 단계: 선정된 문제를 review_queue에 upsert한다.
   이미 큐에 있는 문제는 priority만 갱신하여 중복을 방지한다.

대시보드에서는 reviewed_at IS NULL 조건으로 미복습 문제 수를 실시간 표시하고,
임계값 초과 시 복습 배너를 노출하여 학습자가 취약 개념을 인지하도록 유도한다.

3.6 게이미피케이션

- XP 및 레벨: 문제 정답(문제별 xp_reward) 및 레슨 완료 시 XP 지급.
  Lv.1(0), Lv.2(100), Lv.3(300), Lv.4(600), Lv.5(1000) 이상 400 XP마다 1레벨 상승.
- 하트: 최대 5개. 오답 시 1개 소모. 4시간마다 1개 자동 충전.
  하트 소진 시 학습 불가 상태로 전환하여 과도한 오답 반복을 방지한다.
- 연속 학습 스트릭: KST 기준 전일 대비 연속 학습 여부를 판정하여 스트릭 일수를 갱신한다.
- 리그: bronze·silver·gold·platinum·diamond 5단계로 구분하여 경쟁 동기를 부여한다.


==================================================
IV. 실험 및 평가
==================================================
4.1 구현 결과 개요

제안 시스템을 Next.js 14 기반으로 완전히 구현하고 Supabase 클라우드 환경에 배포하였다.
콘텐츠 규모는 표 1(III장)과 같으며, 문제 유형별 분포는 빈칸 채우기 41%(11문항),
순서 배열 33%(9문항), 논리 흐름 26%(7문항)이다.

4.2 AI 복습 큐 생성 성능

Claude API(claude-haiku-4-5-20251001) 기반 복습 우선순위 산정 응답 시간을 측정하였다.
max_tokens=256 제한 조건에서 오답 문제 20개 입력 시 평균 응답 시간은 약 1.2~1.8초였다.
Haiku 모델을 채택함으로써 Sonnet 대비 약 5배 빠른 응답과 낮은 API 비용을 달성하였다.
API 오류 발생 시 폴백 로직이 즉시 동작하여 서비스 연속성을 보장한다.

4.3 시스템 안정성

- 채점 API(/api/learning/submit): 정답 배열의 대소문자·공백 정규화 후 순서 비교로
  오채점을 방지한다.
- 하트 충전 계산: 서버리스 함수에서 마지막 충전 시각 대비 경과 시간을 계산하므로
  별도 백그라운드 작업 없이 정확한 하트 수를 반환한다.
- 레슨 완료 중복 방지: user_progress에 (user_id, lesson_id) 복합 유니크 제약을 두고
  upsert를 사용하여 중복 XP 지급을 차단한다.

4.4 한계 및 논의

본 연구에서 구현한 콘텐츠(27문항)는 실제 CS 커리큘럼 전체를 커버하기에 제한적이며,
사용자 대상 만족도·정확도 비교 실험은 수행하지 못하였다. 향후 실제 학습자를 대상으로
한 A/B 테스트와 함께 문제 수를 확대할 필요가 있다.


==================================================
V. 결론
==================================================
본 논문에서는 LLM을 활용한 한국어 컴퓨터과학 학습 웹 애플리케이션 CS링고를 설계 및
구현하였다. 제안 시스템은 자료구조·알고리즘·운영체제·네트워크 4개 영역에서 빈칸 채우기·
순서 배열·논리 흐름 세 가지 문제 유형을 제공하며, Claude AI 기반 복습 큐 자동 생성 파이프라인을
통해 학습자 개인화를 실현하였다. XP, 레벨, 하트, 스트릭 기반 게이미피케이션으로 학습 지속성을
높이고, Haiku 모델 활용과 max_tokens 제한으로 API 비용과 응답 시간을 최적화하였다.

향후 연구로는 (1) RAG 기반 사실성 강화, (2) 코드 작성형 문항 추가, (3) 실제 학습자 대상
비교 실험, (4) 문제 콘텐츠 확대(데이터베이스, 자료구조 심화 등)를 계획한다.
